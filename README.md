# 날마다 조식 — 레시피 아카이브

`how.about.breakfast` 다이어리 텍스트(2021.02 ~ 2026.07, 1,831건)를 매거진 스타일
홈페이지 + 검색 아카이브로 만든 정적 웹사이트입니다. 서버·데이터베이스 없이
정적 파일만으로 동작합니다.

## 구성 파일
- `index.html` — **홈페이지**. 6년 기록의 강점을 살린 매거진 스타일 진열대
  - "기록 달력" — 하루도 안 빼먹은 기록을 깃허브 컨트리뷰션 그래프처럼 시각화
  - "오늘 같은 날, 지난 조식들" — 해마다 이맘때 만든 조식을 나란히 비교
  - "소재로 골라 먹기" — 토마토/아보카도/파스타/감자/계란/샌드위치 테마 모음 + 실패기 아카이브
  - "오늘 뭐 먹지?" 무작위 추천 버튼
- `archive.html` — **전체 검색** 페이지 (키워드, 재료 태그, 칼로리, 정렬)
- `styles.css` — 두 페이지가 공유하는 스타일
- `shared.js` — 데이터 로딩 · 카테고리 아이콘 · 상세 팝업 로직 (공유)
- `home.js` — 홈페이지 전용 로직
- `app.js` — 검색 페이지 전용 로직
- `recipes.json` — 파싱된 레시피 데이터 (1,831건)
- `parse.py` — 원본 텍스트 → `recipes.json` 변환 스크립트 (데이터 갱신 시 재사용)
- `merge_instagram_export.py` — 인스타그램 공식 내보내기(사진 포함)를 병합하는 스크립트

## 페이지 이동
홈(`index.html`)의 "소재로 골라 먹기" 카드나 "전체 검색으로 보기" 링크를 누르면
`archive.html?tag=토마토` 처럼 해당 조건이 미리 적용된 검색 페이지로 이동합니다.
"실패기 아카이브" 카드는 `archive.html?failed=1`로 연결됩니다.

## 로컬에서 확인하기
`index.html`을 더블클릭해서 바로 열면 `recipes.json`을 못 불러와요(브라우저 보안
정책 때문). 아래처럼 간단한 로컬 서버를 띄운 뒤 열어주세요.

```bash
cd how-about-breakfast-recipes
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속 (홈페이지부터 보게 됩니다)
```

## 인터넷에 공개하기
정적 파일이라 아무 정적 호스팅 서비스에 폴더째 올리면 바로 됩니다.

**GitHub Pages (무료)**
1. GitHub에 새 저장소 생성
2. 이 폴더의 파일 전체(html/js/css/json)를 업로드
3. 저장소 설정 → Pages → 배포 브랜치 지정
4. 몇 분 후 `https://[아이디].github.io/[저장소명]/` 에서 접속 가능

**Netlify / Vercel (무료, 더 간단)**
- 사이트 폴더를 그대로 드래그 앤 드롭하면 끝.

## 지금 데이터의 한계
- **사진 없음 → 대신 재료별 아이콘**: 실제 사진이 없는 레시피는 재료 태그를 자동
  분류해서 어울리는 심플한 라인 아이콘(14종, 저작권 문제 없는 원본 일러스트,
  `shared.js`의 `ICONS`)을 대신 보여줘요. 사진이 있는 레시피는 자동으로 사진이
  표시됩니다 (`thumbHTML()`이 `image` 필드 유무를 보고 알아서 선택).
- **레시피 구조화율**: 1,831건 중 재료/조리법이 명확히 분리된 건 606건. 2021~2023년
  초반 글은 에세이 형식이라 재료·조리 순서가 따로 안 나뉘어 있어요. 이런 글도 원문
  전체가 검색 대상에는 포함되지만 "재료" 섹션은 비어 있습니다.
- **칼로리 표기**: 436건에만 칼로리가 명시돼 있어요.
- **제목 추출**: 완벽하지 않아요(칼로리 언급 뒤 문구 또는 대표 해시태그로 자동
  추출). 가끔 어색한 제목이 있을 수 있지만, 검색 자체는 원문 전체를 대상으로
  하니 찾는 데는 문제 없습니다.
- **원문의 오탈자**: 아주 드물게(2건) 원본 다이어리 자체에 일련번호 오탈자가
  있어요(예: "11112", "7289"). 원문을 그대로 보존했고, 홈페이지 통계 계산에서만
  영향을 안 받도록 처리했습니다.

## 인스타그램 사진 합치기
6개월치(또는 전체) 인스타그램 공식 내보내기 zip을 받으셨다면:

1. zip을 로컬 아무 폴더에 압축 해제 (예: `~/Downloads/instagram-export`)
2. 이 사이트 폴더(`how-about-breakfast-recipes`)를 로컬에 다운로드
3. 터미널에서 실행:
   ```bash
   cd how-about-breakfast-recipes
   pip install pillow --break-system-packages   # 선택사항, 사진 용량을 크게 줄여줌
   python3 merge_instagram_export.py ~/Downloads/instagram-export .
   ```
4. 완료되면:
   - `recipes.json`이 갱신됨 (매칭된 항목에 `image` 필드 추가, 예전 텍스트 내보내기
     이후 새로 올라온 글은 새 레코드로 자동 추가)
   - `images/` 폴더에 사진이 `{diary_no}.jpg` 이름으로 채워짐 (여러 장이면 `_2`,
     `_3`... 순번으로 갤러리도 함께 저장)
   - 기존 `recipes.json`은 `recipes.backup.json`으로 안전하게 백업됨
   - 사진이 있는 레시피는 카드에 실제 사진이, 없는 레시피는 아이콘이 자동으로
     표시됩니다 (코드 수정 필요 없음)
5. `python3 -m http.server`로 로컬에서 확인 후, 문제없으면 그대로 재배포

**6개월치를 먼저 해보고, 나중에 전체 6년치가 준비되면 같은 명령어를 그 폴더로 다시
실행**하시면 됩니다. 이미 처리된 항목은 덮어써지고, 새 항목은 추가되는 방식이라
여러 번 실행해도 안전해요.

인스타그램 내보내기 특유의 한글 인코딩 버그(Latin-1로 잘못 이스케이프됨)도
스크립트가 자동으로 교정합니다.
